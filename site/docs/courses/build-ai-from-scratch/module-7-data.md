# Module 7: Data

## Learning Objectives

By the end of this module, you will be able to:

- Choose a small training corpus that fits the size of your model
- Implement a streaming dataloader over a tokenized corpus
- Pack tokens efficiently into fixed-length training sequences
- Reason about the relationship between data quality, data quantity,
  and model capability

## The Quiet Truth About Models

The architecture of a transformer is mostly settled. Almost every
serious model in 2026 is the same shape — pre-norm, multi-head
attention, MLP, residuals. What separates a useful model from a
useless one of the same size is, overwhelmingly, the data it was
trained on. Garbage in, garbage out. Carefully curated data in,
something usable out.

This module is the one where you take the data question seriously.

## Choosing a Corpus

For a tiny model in our size range (1–5M parameters), reasonable
choices include:

- **TinyStories** — short, simple stories generated by GPT-3.5,
  designed precisely for training tiny coherent models. About
  500MB. The single best target corpus for this course.
- **Project Gutenberg subset** — a few dozen public-domain books in
  one language. Free, legal, low-noise.
- **A specific domain** — your own writing, a single technical
  documentation set, song lyrics by one band. Smaller, weirder, more
  interesting models.

Avoid: general-purpose web crawls (too noisy for tiny models),
Wikipedia (too encyclopedic, too mixed-domain), Common Crawl (too
much garbage). These corpora are designed for billion-parameter
models that can absorb noise. Yours cannot.

## Tokenizing the Corpus

Once you have raw text, run it through your Module 1 tokenizer
*once* and save the resulting integer stream to disk:

```python
import numpy as np
from tokenizer import BPETokenizer

tok = BPETokenizer()
tok.train(corpus_files, vocab_size=8000)

ids = []
for text in corpus_files:
    ids.extend(tok.encode(text))

# Save as a single contiguous int16 array.
arr = np.array(ids, dtype=np.uint16)
arr.tofile("tokens.bin")
```

A `uint16` array can hold token IDs up to 65,535, which covers any
vocabulary size we will use. Storing as a flat file means the
dataloader can `mmap` it and read random windows efficiently.

## A Real Dataloader

```python
import numpy as np
import torch
from torch.utils.data import Dataset, DataLoader

class TokenStreamDataset(Dataset):
    def __init__(self, path: str, seq_len: int):
        self.tokens = np.memmap(path, dtype=np.uint16, mode="r")
        self.seq_len = seq_len

    def __len__(self) -> int:
        return len(self.tokens) - self.seq_len - 1

    def __getitem__(self, idx: int) -> torch.Tensor:
        chunk = self.tokens[idx : idx + self.seq_len + 1]
        return torch.from_numpy(chunk.astype(np.int64))


def make_loader(path: str, seq_len: int, batch_size: int) -> DataLoader:
    ds = TokenStreamDataset(path, seq_len)
    return DataLoader(
        ds,
        batch_size=batch_size,
        shuffle=True,
        num_workers=2,
        pin_memory=True,
    )
```

Each `__getitem__` returns a chunk of `seq_len + 1` tokens. The
training loop slices this into input (first `seq_len`) and target
(last `seq_len`). This is the cleanest packing scheme for
autoregressive training: every position in the chunk is a valid
training target.

The use of `np.memmap` means we never load the full corpus into
memory — the OS pages it in on demand. For corpora up to a few
gigabytes this works perfectly on a laptop.

## Document Boundaries

If your corpus is many short documents (TinyStories, articles), you
have a choice: either let the model see arbitrary slices of the
concatenated stream (which means some training examples will span
document boundaries — usually fine), or insert a dedicated `<eos>`
token between documents and have the model learn to model it.

For this course, the cleaner approach is to insert `<eos>` between
documents and let the model learn what an end-of-document looks
like. This becomes useful for generation, where you can stop
sampling at the first `<eos>` and produce a single complete
document.

## Quantity

How many tokens do you need? A useful rule of thumb (the Chinchilla
scaling rule): roughly **20 tokens per parameter** is the sweet spot
for compute-optimal training.

For our 1.88M-parameter model, that is roughly **38M tokens**.
TinyStories has about 500M tokens, which is more than ten times what
we need — meaning we will not exhaust the data and the model will
not see any token twice. That is the regime you want.

If you have less data than your model can absorb, you will train
multiple **epochs** (passes through the data). This is fine for very
small datasets but eventually causes memorization rather than
generalization.

## Quality

Quality matters more than quantity past a threshold. Features of a
quality corpus, for our purposes:

- **Single language, single register.** Mixing English and Spanish
  in a 2M-parameter model means the model learns half of each, badly.
- **Short documents.** Tiny models cannot exploit long-range
  dependencies. Short, self-contained documents teach better.
- **Consistent format.** If your corpus has occasional broken HTML,
  rogue Unicode, or inconsistent whitespace, the model will spend
  capacity learning those quirks rather than the language.

Cleaning a corpus is unglamorous work that pays large dividends. A
good tiny model on TinyStories will outperform a tiny model on
mixed web crawl by a wide margin — because the data is curated to
be exactly what a tiny model can use.

## Are-Self Connection

The Hippocampus stores engrams as `(name, description, tags, vector,
relevance)` tuples. When the embedding model that produces those
vectors was trained, the dataset choice mattered enormously: an
embedding model trained on code will represent the sentence "the
function returned None" very differently from an embedding model
trained on novels. Choosing your data is choosing your worldview.

When you train your tiny model in this course, you are also choosing
its worldview. A model trained on TinyStories will write children's
stories and not much else. A model trained on your own writing will
sound like you. This is a feature.

## Think About It

- The "20 tokens per parameter" rule comes from large-scale
  experiments with much bigger models. Why might it still be a
  useful starting point at our scale?
- A model trained on a single author's writing will sound like that
  author. A model trained on the entire English internet will sound
  like an average. Which is a more useful object for what kinds of
  tasks?
- Tokenization happens once, before training. What happens if you
  retrain the tokenizer with a different vocabulary size after the
  model has already trained on the old vocabulary?
